4. `requests.get("https://api.github.com").status_code`가 200이면 무엇을 의미하나?

8차시 — JSON 직렬화·역직렬화·API 언어 연결

1. 딕셔너리를 JSON 문자열로 만드는 함수 이름은?
  json.dumps()
2. JSON 문자열을 딕셔너리로 복원하는 함수 이름은?
  json.loads()
3. (O/X) `json.dumps({"level": 10})` 의 결과 타입은 `dict`다.
  X — 결과는 str(문자열). 딕셔너리로 복원하려면 json.loads() 필요.
4. `ensure_ascii=False`가 필요한 이유를 한 줄로 쓰라.
  ensure_ascii=False가 없으면 한글이 안 같은 유니코드 이스케이프로 출력되어 사람이 읽기 어렵다.
5. (실습) `{"이름": "김보안", "점수": 95}` 를 JSON 문자열로 변환하고, 다시 딕셔너리로 복원해 `점수`만 출력하라.


10차시 — 함수 응용·기본값 인자·리스트 연계

4. `for a in alerts:` 에서 `a` 는 무엇을 가리키는가?
  alerts 리스트의 원소 하나(딕셔너리).
5. (실습) 아래 `alerts` 목록을 `classify` 로 처리하여 `severity` 가 `"High"` 인 항목만 출력하라.
    ```python
    def severity(level):
        if level >= 10: return "High"
        if level >= 7:  return "Medium"
        return "Low"
    def classify(alert):
        sev = severity(alert["level"])
        return {"ip": alert["ip"], "severity": sev}
    
    alerts = [{"level":11,"ip":"5.5.5.5"},{"level":6,"ip":"6.6.6.6"}]
    for a in alerts:
        r = classify(a)
        if r["severity"] == "High":
            print(r)
    # {'ip': '5.5.5.5', 'severity': 'High'}
    ```

4. `r.json()`이 반환하는 자료형은 무엇인가?

14차시 — API · HTTP · GET/POST · 상태코드

1. API는 무엇의 약자이고, 어떤 역할을 하는가?
  API = Application Programming Interface. 프로그램이 다른 서비스를 호출하는 창구(메뉴판) 역할.
2. HTTP에서 **GET**과 **POST**의 사용 목적 차이는?
  GET = 데이터 조회(읽기, URL에 조건). POST = 데이터 전송·생성(바디에 데이터 담음).
3. 상태코드 **401**이 뜨면 무엇이 문제일 가능성이 높은가?
  인증 실패 — API 키나 로그인 자격증명이 없거나 틀림.
4. (O/X) 상태코드 404는 서버가 다운됐다는 뜻이다.
  X — 404는 요청한 URL 경로(리소스)가 없다는 뜻. 서버 다운은 500번대.
5. (실습) `https://api.github.com/nope404_test`에 GET 요청을 보내 상태코드를 출력하라. 몇 번이 나오는가?
  404. URL 경로가 존재하지 않으므로 Not Found.


15차시 — POST · 요청 헤더 · 응답 구조

1. POST 요청에서 실제 데이터는 어디에 담기는가? (URL vs 바디)
  바디(body). GET은 URL 쿼리스트링에, POST는 본문(body)에 데이터를 담는다.
2. `headers={"Content-Type": "application/json"}` 의 역할은 무엇인가?
  서버에게 "내가 보내는 본문은 JSON 형식이다"라고 알리는 역할. 서버가 올바르게 파싱할 수 있게 함.
3. `requests.post(url, json=payload)` 에서 `json=` 파라미터가 자동으로 해주는 일은?
  딕셔너리를 JSON 문자열로 자동 직렬화(json.dumps 자동 실행) 후 바디에 넣는다. Content-Type: application/json도 자동 설정.
4. (O/X) httpbin.org는 받은 요청 내용을 그대로 돌려주므로 내가 보낸 데이터 확인에 유용하다.
  O — httpbin.org는 에코(echo) 테스트 서버로, 받은 요청 전체를 JSON 응답으로 돌려준다. 실습용으로 안전.


16차시 — r.json() · 중첩 구조 · 경보 추출

1. `r.json()`이 반환하는 자료형은 무엇인가?
  딕셔너리 (<class 'dict'>). 응답 JSON을 파이썬 딕셔너리로 자동 변환.
2. `json.loads()`와 `r.json()`의 차이는 무엇인가?
  r.json() = HTTP 응답 객체에서 직접 변환. json.loads() = 어디서든 JSON 문자열을 딕셔너리로 변환. 역할은 같으나 입력이 다름.

    ```json
    {"alerts": [{"id": 1, "ip": "1.1.1.1"}, {"id": 2, "ip": "2.2.2.2"}]}
    ```
  data["alerts"][0]["ip"] → "1.1.1.1" (또는 json.loads(...)["alerts"][0]["ip"])
4. (O/X) `json.loads()`는 딕셔너리를 JSON 문자열로 변환한다.
  X — json.loads()는 JSON 문자열 → 딕셔너리(역방향). 딕셔너리 → JSON 문자열은 json.dumps().

4. n8n에서 Webhook 노드를 실행 대기 상태로 만들려면 무엇을 눌러야 하는가?
  "Listen for test events" 버튼 (또는 "Test workflow" 실행). 이 상태에서만 수신 대기.


18차시 — Webhook → Function 노드 연결 · 경보 분류

1. n8n **Function 노드**에서 이전 노드의 데이터를 읽을 때 쓰는 변수 이름은?
  $json. n8n에서 이전 노드의 출력 데이터를 담는 내장 변수.
2. Function 노드의 코드가 값을 내보낼 때 사용하는 형식은? (힌트: `return [ ... ]`)
  return [{ json: { ...출력할_객체 } }] — 배열 안에 json 키를 가진 객체를 담아 반환.
3. `{ ...$json.body, severity }` 에서 `...` 의 역할은 무엇인가?
  스프레드 연산자 — $json.body의 기존 필드를 모두 펼쳐 복사. 기존 필드를 유지하면서 새 필드(severity)를 추가하는 효과.
4. (O/X) n8n Function 노드는 파이썬으로 코드를 작성한다.
  X — n8n Function 노드는 JavaScript로 작성. 파이썬이 아님(단, 로직·사고방식은 동일).
5. (실습) Function 노드를 수정해 `level >= 10`이면 `priority: 1`, `level >= 7`이면 `priority: 2`, 그 외는 `priority: 3`을 출력 JSON에 추가하라.
    ```jsx
    const level = $json.body.level;
    let priority = 3;
    if (level >= 10) priority = 1;
    else if (level >= 7) priority = 2;
    return [{ json: { ...$json.body, priority } }];
    ```
    출력 예: level 10 → `priority: 1`.


19차시 — CLI 스크립트와 스케줄 자동 실행

1. **CLI**란 무엇인가? 한 줄로 설명하라.

  2026-09-03. %Y=4자리 연도, %m=월, %d=일.

22차시 — LLM 원리·한계·검색 vs 생성

1. **LLM**이 글을 생성하는 핵심 원리를 한 줄로 설명하라.
  "앞 문장을 보고 다음에 올 단어를 확률로 예측하는 과정을 반복해 글을 생성한다."
2. 검색 엔진과 LLM의 가장 큰 차이는?
  검색 엔진은 기존 웹 문서의 링크를 찾아주고, LLM은 질문에 맞는 새 텍스트를 생성한다.
3. (O/X) LLM은 같은 질문에 항상 동일한 답변을 출력한다.
  X — 확률적 생성 과정이므로 같은 질문에 답변이 미묘하게 달라질 수 있다.
4. **환각(Hallucination)**이란 무엇인가?
  환각: LLM이 사실이 아닌 내용을 그럴듯하게, 자신 있게 출력하는 현상. 검증이 필요한 이유.
5. LLM이 오늘 발생한 사건을 모르는 이유는?
  학습 시점(Cutoff) 제한: 모델을 학습시킨 날짜 이후의 사건은 학습 데이터에 없어 알 수 없다.


23차시 — 좋은 프롬프트 3요소·나쁜 vs 좋은 비교

1. 좋은 프롬프트의 **3요소**를 쓰라.
  역할(Role) + 맥락(Context) + 출력형식(Format).
2. (O/X) "이 경보 분석해줘"는 좋은 프롬프트다.
  X — 경보 데이터도 없고 출력형식도 없는 막연한 지시. 좋은 프롬프트가 아니다.
3. 출력형식을 **JSON**으로 지정하는 이유는?
  Python json.loads() 또는 r.json()으로 자동 파싱 가능. 자유 문장은 파싱이 어려워 자동화에 쓸 수 없다.
4. "너는 보안 분석가다"처럼 역할을 명시하면 어떤 효과가 있는가?
  AI가 해당 분야 전문가의 관점과 어휘로 답변한다. 보안 분석가 → 보안 용어·분류 기준으로, 법무 변호사 → 법적 관점으로.
5. (서술) LLM 응답을 Python 코드가 자동 처리하려면 어떤 출력형식이 유리한가? 이유는?
  JSON이 유리. 구조가 정해져 있어 키로 값을 꺼낼 수 있고(예: r["severity"]), 자동화 파이프라인에서 다음 단계로 바로 전달 가능.


24차시 — 프롬프트 템플릿·재사용·반복 개선

1. **프롬프트 템플릿**이란 무엇인가?
  프롬프트 템플릿: 고정 지시문은 그대로 두고, 달라지는 데이터 부분만 변수로 비워둔 재사용 가능한 프롬프트 형식.
2. Python에서 변수를 문자열 안에 삽입하는 문법의 이름은?
  f-string (포맷 문자열 리터럴) — f"..." 안에 {변수}를 사용.
3. (O/X) `f"안녕 {name}"` 에서 `name = "Alice"` 이면 출력은 `"안녕 Alice"` 이다.
  O — f-string에서 {name}이 "Alice"로 치환되어 "안녕 Alice"` 출력.
4. 프롬프트 템플릿을 함수로 만들면 어떤 이점이 있는가?
  지시문을 한 곳에서만 관리(DRY)·경보 건수에 관계없이 한 번만 정의·지시문 수정 시 함수만 고치면 전체 적용.
5. **반복 개선(Iteration)**이란 무엇인가?
  반복 개선: 결과를 확인 → 문제점 파악 → 프롬프트 수정 → 재실행하는 사이클. 한 번에 완벽한 프롬프트를 쓸 필요 없이 점진적으로 개선한다.
6. (실습) `make_prompt({"rule": 1002, "level": 8, "ip": "2.2.2.2"})` 의 출력을 적어라.
    ```
    너는 사이버 보안 분석가다.
    아래 경보를 분석해 심각도·요약·권고를 포함한 JSON으로 답하라.
    다른 설명 없이 JSON만 출력하라.
    
    경보: {'rule': 1002, 'level': 8, 'ip': '2.2.2.2'}
    ```

26차시 — AI 에이전트 개념·루프 4단계·구성요소

1. AI 에이전트의 루프 4단계를 순서대로 쓰라. (인식 → __ → __ → __)
  인식 → 계획 → 도구 호출 → 관찰 (→ 반복).
2. 에이전트의 4가지 구성요소는? (LLM · __ · __ · __)
  LLM(두뇌) · 도구(Tool) · 메모리 · 오케스트레이션.
3. (O/X) 에이전트는 반드시 LLM이 있어야 동작한다.
  X — LLM 없이 룰 폴백(규칙 기반 함수)으로 동작 가능. 재현성·비용 면에서 오히려 유리한 경우 많음.
4. 이번 실습에서 "도구(Tool)" 역할을 한 함수의 이름은?

27차시 — 미니 에이전트 구현·룰 폴백·n8n 연결

1. 룰 폴백(Rule Fallback)이란 무엇인가?
  LLM API 키 없이(또는 API 장애 시) 규칙 기반 함수로 대신 처리하는 안전장치.
2. LLM 키 없이 에이전트를 동작시킬 때 생기는 장점 2가지를 써라.
  ① 재현성(같은 입력 → 항상 같은 결과) ② 비용 절감(토큰 사용 없음) (③ 장애 내성도 정답).
3. (O/X) 룰 폴백을 쓰면 LLM 결과와 항상 같은 결과가 나온다.
  X — 룰 폴백은 항상 같은 결과, LLM은 확률적으로 다를 수 있다. 룰 폴백이 오히려 일관성이 높음.
4. `agent_run({"rule": 9, "level": 8, "ip": "4.4.4.4"})`의 출력에서 `severity` 값은?
  "Medium" (level 8 → 7 이상이므로 Medium).


28차시 — RAG 개념·키워드 매칭·근거 첨부

1. RAG의 풀 이름(영어)과 한국어 뜻을 쓰라.
  Retrieval-Augmented Generation, 검색증강생성.
2. RAG가 환각을 줄이는 원리를 한 문장으로.
  관련 문서를 근거로 첨부해 LLM이 그 내용 안에서 답하도록 제약함으로써 틀린 내용 생성(환각)을 줄인다.
3. (O/X) RAG는 벡터 검색이 없으면 구현할 수 없다.
  X — 오늘처럼 키워드 매칭 딕셔너리로도 구현 가능. 벡터 검색은 의미 유사도 기반 심화 방식.
4. `rag_search("mfa 설정")`의 반환값은?
  "MFA는 다중 인증으로 비밀번호 탈취 후에도 계정을 보호한다."
5. (실습) `rag_search("방화벽")`의 출력을 적고, 이 경우 LLM에게 어떤 위험이 있는지 한 줄로.
  "관련 문서 없음" 반환. 이 경우 LLM은 근거 없이 학습 데이터만으로 답해야 하므로 환각 위험이 높아진다.


29차시 — 환각·비용·민감정보 마스킹

1. LLM 사용의 3대 주의점을 쓰라.
  환각(사람 검증 필수) · 비용(토큰 한도) · 민감정보(마스킹 후 전송).
2. 마스킹(Masking)이 필요한 이유를 한 문장으로.
  전화번호·이메일 등 개인정보가 외부 LLM 서버에 전달되지 않도록 보호하기 위해.
3. (O/X) `re.sub()`는 패턴을 찾아 **모든** 매칭 부분을 교체한다.
  O — re.sub()는 패턴과 일치하는 모든 부분을 교체한다(첫 번째만 교체하려면 count=1 옵션 사용).
4. `\d{3}-\d{4}-\d{4}` 패턴이 매칭하는 형식의 예를 하나 써라.
  010-1234-5678 (또는 011-0000-1111 등 숫자 3-4-4 패턴).
5. (실습) `mask_sensitive("연락처 010-5555-6666, test@mail.com")`의 출력을 적어라.
  "연락처 ***-****-****, ***@***.***".


30차시 — 안전 체크리스트·human-in-the-loop·SOAR 연결 예고

1. human-in-the-loop 란 무엇인가?
  AI 에이전트가 고위험 행동을 실행하기 전 반드시 사람이 확인·승인하는 설계 패턴.
2. 안전 운영 3원칙(환각·비용·민감정보)을 각각 한 줄로.
  ① 환각: AI 출력을 그대로 쓰지 않고 사람이 검증한다. 
  ② 비용: 토큰 예산을 설정하고 불필요한 호출을 줄인다. 
  ③ 민감정보: PII는 마스킹 후 LLM에 전달한다.
3. (O/X) `safe_action()`에서 `risk_level=5`이면 사람 확인 없이 자동 실행된다.
  O — risk_level=5 < 8이므로 사람 확인 없이 자동 실행.
4. `safe_action("계정 잠금", risk_level=9)`을 실행하면 어떤 일이 일어나는가?
  risk_level=9 ≥ 8이므로 터미널에 확인 메시지가 뜨고, y/n 입력을 기다린다.
5. (서술) C파트 6개 소단원의 흐름을 화살표(→)로 한 줄에 정리하라.
  LLM이란 → 프롬프트 → API 키 관리 → AI 에이전트 → RAG → 안전·비용·환각.


31차시 — 미니 자동화 봇 통합 구현

1. 미니 봇 파이프라인 5단계를 순서대로 쓰라(키워드: 정규화·분류·요약·출력).
  JSON 입력 → 정규화(마스킹 포함) → 분류(룰 폴백) → 요약 → 결과 출력.
2. `severity(9)`의 반환값은?
  "Medium" — level >= 7 조건을 만족, level >= 10 은 불만족.
3. (O/X) `mask_sensitive`를 적용하면 원본 `raw_alert` 딕셔너리 안의 IP도 바뀐다.
  X — dict(raw_alert)로 복사본을 만들어 처리하므로 원본은 변하지 않는다.
4. `process_alert` 안에서 `dict(raw_alert)`를 쓰는 이유는?
  함수 안에서 딕셔너리를 수정할 때 원본이 바뀌는 부작용(사이드 이펙트)을 막기 위해 복사본을 사용한다.
5. `os.environ.get("ANTHROPIC_API_KEY")`가 `None`일 때, 봇은 어떻게 동작하는가?
  key가 None이므로 if key: 분기를 건너뛰어 룰 기반 summary 문장이 그대로 사용된다. 봇은 멈추지 않는다.
6. (실습) `sample_alerts`에 경보 1건(`{"rule": 9999, "level": 7, "ip": "5.5.5.5"}`)을 추가하고 결과를 확인하라.
  추가 후 4번째 줄: {"severity": "Medium", "ip": "5.5.5.5", "summary": "Medium 경보: IP 5.5.5.5, rule 9999", "ts": "..."}.


32차시 — Markdown 리포트 생성·발표·모듈 마무리

1. `with open("파일", "w", encoding="utf-8")` 에서 `"w"` 모드의 의미는?
  쓰기 모드(write) — 파일이 없으면 생성, 있으면 처음부터 덮어쓴다. 누적하려면 "a" (append) 모드.
2. Markdown 테이블에서 헤더 다음 줄에 반드시 넣어야 하는 것은?
  |---|---|...| 구분선 — 이 줄이 없으면 Markdown 렌더러가 테이블로 인식하지 않아 일반 텍스트로 출력된다.
3. (O/X) `results` 리스트 안의 딕셔너리를 파일에 쓸 때 `json.dumps()`를 써야 한다.
  X — 리포트 파일에는 f-string으로 Markdown 형식 문자열을 직접 쓴다. json.dumps()는 JSON 문자열 출력용.
4. 생성된 `mini_bot_report.md`에 경보가 4건이 되려면 코드 어디를 수정하나?
  sample_alerts 리스트에 딕셔너리 1개를 추가하면 된다. results 생성·리포트 작성 코드는 수정 불필요.
5. (서술) 모듈 02에서 배운 내용을 `A → B → C → 봇` 순으로 각 한 줄씩 정리하라.
  A=파이썬 기본 문법(변수·조건·반복·함수·파일), B=HTTP API·Webhook·n8n 자동화, C=LLM 프롬프트·에이전트·안전, 봇=A~C를 합쳐 경보→분류→리포트 흐름 완성.
6. (서술) 이 미니 봇과 **05 SOAR**(다음 모듈)의 관계를 한 줄로 설명하라.
  미니 봇 파이프라인(분류→요약→리포트)이 05 SOAR에서 Wazuh 실제 경보·n8n 플레이북·자동 대응으로 확장된다.
